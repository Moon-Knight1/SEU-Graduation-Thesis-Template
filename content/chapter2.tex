\chapter{相关开发技术介绍}
为了提高系统的开发效率与可维护性，本文在系统开发过程中采用了当前较为成熟的企业级开发技术与相关框架（如后端框架 Spring Boot，前端框架 Vue）。这些技术能够有效支持系统的功能实现、数据管理以及前后端交互，同时也有助于提升系统的稳定性与扩展性。下面将对本系统开发过程中使用的主要技术进行介绍。

\section{Spring Boot框架}
在企业级系统开发中，稳定性是需要优先考虑的因素。Java 自 1995 年问世以来，经过多年发展，已经在企业应用领域形成了较成熟的运行机制。依托 JVM\cite{oracle2015jvms8}（Java Virtual Machine），Java 具备较好的跨平台能力，能够实现“一次编写，到处运行”，便于系统在不同环境中的部署和迁移，常用于开发 Web 应用程序。企业开发同样重视技术生态。Java 拥有较完善的框架和工具链。在众多 Java 后端开发框架中，Spring Boot 以快速开发和生态丰富的优势占据了主要地位。下面从其核心理念与关键特性两个方面进行介绍。
\subsection{Spring Boot框架核心理念}
在 Java 企业级应用开发中，Spring、Spring MVC 与 MyBatis 等传统架构需要维护较多的 XML 配置文件，手工管理依赖版本并执行多步骤部署流程。启动新项目时，开发者需投入相当一部分时间处理框架整合与组件装配，而非直接编写业务代码。Spring Boot的设计目标正是减少这一部分非功能性的搭建开销。

Spring Boot 是 Spring 生态的扩展，其核心机制为“约定大于配置”\cite{springboot2025autoconfig}：框架为常见场景预设了默认参数，开发者无需从零编写样板配置即可启动应用。在日常开发中，通过注解即可完成Bean的注册与依赖装配，省去了显式的XML声明或工厂方法。这一方式使开发者能将精力集中于业务逻辑，而非底层环境搭建，降低了初始配置的复杂度。
\subsection{Spring Boot框架关键特性}
Spring Boot相较于传统 SSM（Spring + SpringMVC + MyBatis），主要在以下四个方面做了简化：
\begin{enumerate}[label=(\arabic*)]
	\item \textbf{控制反转与依赖注入：}
	Spring Boot 延续了 Spring 的 IoC（Inversion of Control）容器机制。对象的创建与生命周期由容器统一管理，不再由开发者在代码中实例化，开发者通过注解声明依赖关系，容器在运行时自动注入关联实例。这一机制降低了模块间的编译期耦合，也便于单元测试时替换桩实现，同时还减少了冗余代码量。
	\item \textbf{起步依赖：}
	框架将特定功能场景所需的依赖库封装为标准化的 Starter\cite{springboot2025starters}。开发者在 pom.xml 中引入对应 Starter 后，Maven 自动解析并下载所有传递性依赖，避免了手动排查版本冲突的问题。
	\item \textbf{外部化配置：}
	系统在开发、测试与生产环境中通常需要不同的数据库连接、中间件地址和第三方密钥。Spring Boot支持通过application.yml为不同环境预设独立的配置文件\cite{springboot2025externalconfig}，并在启动时通过命令行参数、环境变量或配置中心指定激活的配置集，无需重新编译即可切换运行环境。
	\item \textbf{内嵌式运行容器：}
	传统 Java Web 应用需先部署到外部 Tomcat 服务器再启动。Spring Boot 直接将 Tomcat 容器集成到项目中，通过 mvn package 打包为独立可执行 Jar 包\cite{springboot2025packaging}，使用 java -jar 命令即可启动服务，减少了独立部署与运维配置的步骤。
	% 表格与下文之间空一行
\end{enumerate}

Spring Boot 的自动装配与内嵌容器机制能够减少项目初始化、依赖配置和部署配置中的重复工作，IoC 容器与起步依赖有助于降低模块间的耦合度。结合本系统在开发过程中需要频繁迭代功能、快速验证业务逻辑的实际需求，本文选择 Spring Boot 作为后端开发框架。

\section{Vue框架}
Vue\cite{vuejs2023guide}是一个轻量级前端框架，采用"渐进式"设计。开发者既可以将其用于页面局部功能增强，也可以结合路由、状态管理和构建工具等生态组件构建单页面应用（Single Page Application, SPA）。与直接操作 DOM（Document Object Model）的传统开发方式相比，Vue 遵循 MVVM\cite{fuksa2025mvvm}（Model-View-ViewModel）架构模式，如图~\ref{fig:mvvm-pattern-diagram}所示。
\begin{figure}[htbp]
	\centering
	\includegraphics[width=0.5\linewidth]{imgs/MVVM模式图.png}
	\caption{MVVM模式图}
	\label{fig:mvvm-pattern-diagram}
\end{figure}

在 MVVM 架构中，Model 层存储数据状态与业务逻辑；View 层对应页面呈现；ViewModel 层则承担二者之间的数据绑定与交互协调作用。当 Model 数据变化时，View 可根据绑定关系自动更新；当用户与 View 交互时，Model 的数据同步被修改。这种双向绑定省去了手动操作 DOM 的步骤，开发者可以专注于业务数据的流转。

与 React、Angular 等其他常用前端框架相比，Vue 更适合本系统的前端开发需求。React 具有较强的灵活性，适合复杂交互界面的开发，但工程结构通常需要开发团队自行组织；Angular 提供了较完整的工程体系和开发规范，但框架体量较大，学习和维护成本相对较高。Vue 的模板语法较为直观，组件化开发方式清晰，项目结构也相对轻量。结合本系统以表单录入、表格查询、条件筛选和统计展示为主的后台管理场景，Vue 能够在开发效率、页面维护性和后续扩展性之间取得较好平衡，因此本文前端部分选择 Vue 作为主要开发框架。

在本系统前端实现中，Vue 比较擅长页面组件组织、用户交互处理等工作，但对于图表绘制和可视化交互的场景支持有限。因此需要使用 ECharts 库来处理这部分工作，它是一款基于 JavaScript 的开源 Web 数据可视化库，支持折线图、柱状图、饼图等常见图表类型\cite{apacheecharts2025getstarted}。

\section{数据库技术}
在企业级 Web 应用中，业务数据通常需要长期保存。因此，系统在数据存储层采用 MySQL 保存业务数据。同时，考虑到部分基础数据和统计结果会被前端页面反复访问，系统引入 Redis 作为缓存组件，减少重复查询数据库带来的开销，提高接口响应速度。
\subsection{关系型数据库MySQL}
MySQL 是应用较为广泛的开源关系型数据库管理系统，具有部署成本低、使用门槛低、社区资料丰富等特点，能够满足本系统业务数据存储、条件查询和统计分析的需要。相比 Oracle，MySQL 开源免费，更适合企业内部管理平台的开发与部署；相比 PostgreSQL，MySQL 在国内 Web 后端开发中应用更普遍，相关工具、驱动和开发经验也更容易获取。因此，本文选择 MySQL 作为系统的关系型数据库，其运行机制如图~\ref{fig:sql-execution-diagram}所示。

客户端通过 TCP 协议连上 MySQL 服务后，会先进行权限校验和身份确认，这一步由连接器负责，为了提高速度和资源利用率，MySQL 会用连接池来进行连接。接着，系统会看看之前有没有执行过一模一样的 SQL（但是在最新的 MySQL 版本中因为命中率太低被移除了）。之后这条查询语句会走到解析器那里，做词法和语法检查，看看语句写得对不对；然后再交给预处理器，验证里面涉及的表和字段是不是真的存在。再往后就是优化器，它会根据各种情况计算哪种执行方案成本最低，比如决定用哪个索引来查。最后执行器按这个计划去调用存储引擎提供的接口，把符合条件的记录一条条取出来，最终将结果集打包返回给客户端。

本系统选用 MySQL 默认的 InnoDB 存储引擎\cite{mysql2024innodb}。InnoDB 支持事务处理，能够较好地保证业务数据在修改过程中的一致性。其索引底层通常采用 B+ 树结构，有利于减少磁盘 I/O，提高条件查询效率。同时，InnoDB 还支持 MVCC\cite{mysql2024mvcc}（Multi-Version Concurrency Control）和行级锁机制，在多用户同时访问系统时，可以在一定程度上降低读写冲突对业务操作的影响，保证并发环境下的数据隔离性和可靠性。
\subsection{非关系型数据库Redis}
MySQL 能够提供稳定可靠的数据持久化服务，但在面对访问频率较高且数据结构相对简单的场景，如果每次都直接访问数据库，会增加数据库压力，也会影响接口响应速度。因此，本系统引入了 Redis 作为缓存中间件。Redis 本质上是一款由 C 语言实现的，基于内存的高性能键值对存储系统，由于其数据读写操作主要在内存中进行，因此具有较低的访问延迟。除了基础的字符串类型，Redis 还原生支持哈希、列表、集合、有序集合等丰富的数据类型，开发者能够很便捷地将其应用于排行榜、分布式锁、打卡签到等场景\cite{redis2025datatypes}。为了兼顾数据安全性，Redis 提供了 RDB 快照和 AOF 日志两种持久化方式，前者定期保存全量数据，后者以追加形式记录每条写命令，两者可组合使用以平衡恢复速度与数据完整性\cite{redis2025persistence}。在性能方面，Redis 采用单线程模型处理命令，避免了多线程的锁竞争和上下文切换开销，同时借助 I/O 多路复用技术让单个主线程能够并发处理大量客户端连接。基于以上特性，在流量较大或者数据库查询比较慢的接口，引入 Redis 可以有效减少到达数据库的请求数量，提高系统的性能和稳定性。

在缓存组件选型时，本系统没有采用 Memcached\cite{memcached2025userguide}，原因在于 Memcached 更适合简单的键值缓存场景，而本系统后续可能涉及对象缓存、权限信息缓存以及统计结果缓存等多种数据形式。Redis 在数据结构、持久化能力和功能扩展方面更符合系统需求，并且支持通过 Lua 脚本将多个操作组合为原子执行\cite{redis2025lua}。因此，综合系统功能扩展、数据结构适配和后续维护成本，Redis 更适合作为本系统的缓存中间件。

\section{MyBatis-Plus}

MyBatis-Plus\cite{baomidou2025} 是在 MyBatis 基础上扩展的ORM（Object-Relational Mapping）框架，其设计理念是“只做增强不做改变”，即在保留 MyBatis 原有使用方式的基础上，进一步简化常见数据库操作。在后台管理类系统中，数据访问层通常包含大量结构相似的增删改查代码，如果全部手动编写 Mapper 方法和 SQL 语句，容易造成代码重复，也会增加后期维护成本。因此，本文在持久层开发中引入 MyBatis-Plus，用于简化基础数据访问逻辑。

在具体使用时，持久层接口可以通过继承 BaseMapper 获得常用的单表增删改查方法，开发者只需定义实体类与数据库表之间的映射关系，便可完成大部分基础数据操作。对于带有不固定查询条件的接口，MyBatis-Plus 提供了 QueryWrapper、LambdaQueryWrapper 等条件构造器，可以根据前端传入的参数动态生成查询条件，避免在代码中手动拼接 SQL 字符串。对于列表类页面中常见的分页查询需求，MyBatis-Plus 也提供了分页支持，能够配合页码、每页条数等参数返回对应范围的数据结果。

MyBatis-Plus 并不会限制原有 MyBatis 的使用方式。对于单表操作和简单条件查询，可以使用框架提供的通用方法完成；对于多表关联、复杂统计等场景，仍然可以在 Mapper XML 文件中编写自定义 SQL。通过这种方式，系统既能够减少基础持久层代码的重复编写，又能保留复杂查询场景下的灵活性。

\section{本章小结}

本章介绍了系统开发中使用的几项技术：后端采用 Spring Boot 框架，借助自动装配和内嵌容器机制简化服务端开发与部署；前端选用 Vue 框架，通过 MVVM 模式实现数据与视图之间的联动，降低页面交互开发的复杂度；数据层采用 MySQL 与 Redis 组合，前者负责业务数据的持久化存储，后者用于缓存部分访问频率较高的数据；持久层使用 MyBatis-Plus 减少基础 CRUD 代码的重复编写；数据可视化部分则通过 ECharts 完成图表展示。上述技术为后续系统需求分析、功能设计与实现提供了基础支撑。
