\chapter{系统总体设计}
软件架构描述了系统的顶层组织方式和结构设计，包括由哪些核心组件构成、各组件承担何种职责、模块之间如何协作，以及系统如何与数据库、缓存、中间件和外部平台交互。与代码实现细节不同，软件架构更关注系统的分层策略、模块边界、数据流向和扩展能力，目的是从宏观层面厘清“为什么这样设计”和“系统如何运转”，为后续的功能实现、数据库设计、接口定义和系统部署提供基础依据。本章将沿着“前端请求 → 后端服务 → 数据库层”这一主线展开分析。

\section{系统整体架构设计}
当前系统采用前后端分离的 B/S（Browser/Server）架构。用户通过浏览器访问系统前端页面，前端负责界面展示、交互控制、状态管理和图表可视化；后端负责认证授权、业务处理、流程流转、数据访问、缓存管理和外部系统集成。整体上，该系统属于单体式多模块业务系统。基于此，将系统自上而下纵向切分为四个相互隔离的逻辑层，各层之间严格通过接口协议进行单向依赖通信。

第一层为\textbf{前端展示层}。
负责直接与用户进行交互：向后端发起网络请求，然后在响应中拿到数据，最后完成可视化渲染。由于系统涉及大量的复杂表格和数据图。前端基于 Vue 框架的组件化思想构建单页面应用，利用其双向数据绑定特性和Element UI/Ant Design Vue组件库，快速完成“项目管理”模块中海量表单的交互与录入。在业务状态管理方面，系统采用 Vuex 进行集中式状态管理。通过 Vuex 的模块化设计（划分 account 和 setting 模块），将用户认证信息（JWT Token）、细粒度权限管控数据（Permissions）以及系统全局 UI 配置（主题色、布局风格等）进行统一存储。配合 LocalStorage 实现状态数据的本地持久化，确保用户刷新页面时状态不丢失。在业务线中（如“项目管理”及“软件风险管控”等模块），前端组件通过直接挂载 Vuex 状态进行身份识别与按钮级别的权限拦截（如动态控制操作人权限及表单默认值）；当用户进行权限切换或全局主题配置更改时，Vuex 的响应式机制能够实时捕获状态变化并通知所有嵌套子组件完成即时重绘，从而保障了多组件间跨层级数据流转的一致性与可维护性。针对 PMO 角色KPI数据查看和工时统计分析需求，引入 ECharts 数据可视化库，将后端传来的海量基础数据渲染为直观的工时占比饼图和工时趋势折线图。由 Axios 负责统一向后端发起异步的 Restful API 请求，以保障页面无刷新的流畅体验。

第二层为\textbf{安全拦截层}。
作为后端服务的统一“过滤器”，负责所有 HTTP 请求的合法性校验与细粒度的权限校验。本项目采用 Vue + Spring Boot 的前后端分离架构，传统的基于 Session 认证机制存在跨域受限和状态维持开销大的痛点。同时，作为企业级运营平台，系统必须满足内部统一身份认证（LDAP）、严格的数据越权访问拦截，以及对在线用户的实时治理（如强制下线）。为此，本系统基于 JWT + Apache Shiro + Redis 构建了一套无状态、高安全性的混合鉴权架构。登录接口首先对接企业 LDAP 服务完成统一身份核验。随后签发 JWT 实现无状态的跨域认证。为提升传输安全性，系统在 JWT 外层增加了对称加密，有效防止 Token 被网络抓包篡改。为避免复杂权限校验引发数据库 I/O 瓶颈，系统将用户角色与权限树全量预热至 Redis 缓存，在内存中完成极低延迟的权限比对，并且每次请求都要求携带 Token 前往 Redis 中校验有效性。同时将签发的 Token 与客户端 IP 地址绑定存入 Redis，一旦检测到 IP 变动或异地登录，系统将自动拦截该请求，防止令牌盗用。此外，针对 JWT 自身“一旦签发无法撤销”的技术缺陷，我们使用 Redis 追踪在线用户，管理员可通过主动清除缓存中记录与对应拼接了 IP 后缀的 Token 缓存，实现对违规用户的“强制下线”管控。所有的 HTTP 请求在触达业务层前必须经过此层。系统在此部署了 Shiro Filter Chain 拦截器，提取请求头中的 JWT 令牌进行无状态的身份验权。此外，还利用 Spring AOP 机制，使用自定义注解对登录接口实现限流。

第三层为\textbf{核心业务层}。
该层主要完成对请求的具体业务逻辑的处理，后端需快速处理复杂的工时核算与统计逻辑，同时必须解决“数据孤岛”问题，自动获取外部考勤和缺陷数据。系统基于 Spring Boot 框架搭建，系统管理模块主要负责平台基础权限与组织架构的维护；公司运营模块负责处理人员、工时等数据的流转；项目管理模块处理从立项到交付的全生命周期追踪；定时任务模块则负责后台周期性数据快照和同步任务。同时，该层还会调用外部的飞书 API 和 Jira 接口，完成考勤和缺陷数据的跨系统流转。

第四层为\textbf{数据层}。负责业务数据与系统配置的安全落地，提供海量数据的快速读写能力。在“数据持久层”，核心业务数据统一存放于 MySQL 关系型数据库，并引入 MyBatis-Plus 框架消除大量重复的单表 CRUD SQL 代码，提高开发效率。针对性能瓶颈，系统引入 Redis 分布式缓存中间件：将高频访问且极少变动的数据（如部门组织树结构），以及耗时较长的“工时统计分析”提前预热写入 Redis 内存中。当 PMO 访问看板时，数据直接从内存击中返回，从而实现毫秒级的高速响应，有效保护底层数据库。

\section{系统功能模块划分}
在上述分层架构的基础上，从业务维度对后端工程进行横向模块划分，将系统拆分为三个核心业务域：系统管理、公司运营管理和项目运营管理，以降低模块间的耦合度并提升代码的可维护性。在后端工程的代码组织上，如果将所有的 Controller 或者 Service 混杂在同一个包下，随着时间的推移，类越来越多，不利于开发人员进行代码的维护和拓展。因此，将工程结构划分为三个软件包：system，companyM，projectM。

\begin{enumerate}[label=(\arabic*)]
	\item \textbf{系统管理模块：}
	该模块对应后端 systemM 包，作为整个运营平台的底层基座，负责平台基础管理功能。其核心内容包括用户管理、角色管理、菜单管理、部门管理、日志管理、在线用户管理和权限控制。该模块为整个系统提供统一的认证授权基础，也是动态菜单和按钮权限控制的核心来源。这个模块是项目初始脚手架自带的，主要涉及八张数据库表。
	用户表 \verb|t_user| 存储系统登录账户信息，角色表 \verb|t_role| 存储角色定义，菜单表 \verb|t_menu| 存储前端动态菜单和按钮权限项，用户角色关联表 \verb|t_user_role| 和角色菜单关联表 \verb|t_role_menu| 用于构建 RBAC 权限模型，部门表 \verb|t_dept| 用于维护组织层级，日志表 \verb|t_log| 与 \verb|t_login_log| 用于记录用户操作和登录行为。
	
	\item \textbf{公司运营管理模块：}
	该模块对应后端 companyM 包，聚焦于企业人力资源的度量分析，主要负责员工、组织、工时、KPI 等企业基础管理和统计分析功能。其主要业务包括员工信息管理、组织结构查询、工时统计分析、KPI 指标统计。我负责该模块中“工时统计分析”下的 BU 工时分布功能。主要涉及四张数据库表：
	\verb|tb_emp_baseinfo| 存储员工基础信息，\verb|tb_org_tree| 存储组织树结构，\verb|tb_sync_wh| 存储从外部系统同步而来的工时记录，\verb|tb_sync_attend_hour| 存储考勤工时数据，用于计算加班工时。该模块既为项目管理提供人员和组织信息支撑，也为管理层提供多维度工时和绩效分析能力。

\section{本章小结}
本章主要对玄武数字化项目管理平台进行了总体规划与设计。首先从宏观角度阐述了系统的四层技术架构，包含前端展示层、安全拦截层、核心业务层与数据持久层，明确了前后端分离的通信机制及各层的核心技术栈选型。随后，从实际业务维度出发，将系统横向解耦为系统管理、公司运营管理和项目运营管理三大核心模块，并详细梳理了各模块的职责边界与所包含的具体功能。
