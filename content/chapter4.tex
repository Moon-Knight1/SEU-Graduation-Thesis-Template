\chapter{系统总体设计}
软件架构是对系统整体结构和运行方式的抽象描述，主要用于说明系统由哪些部分组成、各组件承担何种职责、各部分之间如何协作，为后续的功能实现和数据库设计提供基础依据。合理的软件架构能够使系统功能划分更加清晰，也便于后续的开发、维护和扩展。在进行系统总体设计时，需要先确定系统采用的架构模式，再在此基础上设计各功能模块和数据交互方式。

从应用系统的运行模式来看，常见的软件架构主要包括 C/S 架构和 B/S 架构两类。C/S 架构即 Client/Server 架构，系统由客户端和服务器端两部分组成。客户端通常需要安装专门的软件，负责界面展示和部分业务处理，服务器端主要负责数据存储、核心业务逻辑处理和资源管理。该架构在交互性能和本地资源调用方面具有一定优势，但客户端安装、升级和维护成本较高，当使用终端数量较多时，版本管理也相对复杂。

B/S 架构即 Browser/Server 架构，是在 C/S 架构基础上发展起来的一种应用模式。用户通过浏览器访问系统，不需要在本地安装专门客户端，主要业务逻辑集中部署在服务器端，浏览器负责页面展示和用户交互。该架构具有部署简单、维护方便和跨终端访问能力较强等特点，适合企业内部信息管理系统和 Web 应用系统。由于系统升级主要在服务器端完成，用户侧不需要频繁更新客户端，可以降低后期运维成本。因此，当前系统采用 B/S 模式。

\section{系统整体架构设计}
为了降低模块之间的耦合度，并提高系统后续维护和扩展的便利性，本文在整体架构设计中采用分层设计思想，将系统划分为前端展示层、安全拦截层、业务逻辑层和数据持久层四个部分。各层之间按照相对明确的调用关系进行协作，上层主要负责接收用户请求和展示处理结果，下层则负责业务处理、数据访问和数据持久化。

具体而言，表示层由前端页面组成，负责用户交互、数据展示和请求发送；业务逻辑层负责处理项目管理、公司运营管理等核心业务规则；数据访问层负责封装对数据库的访问操作；数据存储层则用于保存系统运行过程中产生和同步的业务数据。通过这种分层方式，系统的页面展示、业务处理和数据操作能够保持相对独立，有利于提高系统结构的清晰度。系统整体架构如图~\ref{fig:system-architecture} 所示。

第一层为\textbf{前端展示层}。
负责系统页面展示、用户交互和数据可视化等工作。本系统前端基于 Vue 进行开发，页面组件和基础交互控件主要采用 Ant Design Vue 实现，能够满足表单、表格、按钮、弹窗等后台管理系统常见界面的开发需求。对于数据展示场景，系统使用 ECharts 绘制柱状图、折线图、饼图等可视化图表，使用户能够更直观地理解统计结果。前端通过 Axios 与后端接口进行 HTTP 通信，然后从后端返回的JSON格式中拿到数据。前端项目运行环境依赖 Node.js，并通过 npm 管理前端依赖，使用 Webpack 完成项目打包和资源构建。

第二层为\textbf{安全拦截层}。
安全拦截层位于前端请求和后端业务处理之间，主要负责身份认证、权限校验和接口访问控制，作为后端服务的统一“过滤器”。本系统使用 Shiro 安全框架实现用户认证与授权管理，通过 JWT 在用户登录后颁发身份令牌，前端在访问登录接口后拿到令牌并保存到本地，后续所有请求都在请求头中携带该令牌，后端对令牌有效性和用户权限进行校验。用户登录时，系统结合 LDAP 进行身份认证，以便与企业内部账号体系保持一致。除身份和权限控制外，系统还通过 AOP 自定义注解方式对部分接口进行限流处理，避免短时间内重复请求对系统造成过大压力，从而提高接口访问的安全性和稳定性。

第三层为\textbf{业务逻辑层}。
该层是系统后端的核心部分，主要负责项目管理、公司运营管理等业务功能的处理。前端发起的 HTTP 请求在通过安全校验后，会根据请求方式和请求路径分发到对应的后端接口，并进入具体的业务模块。
在业务处理过程中，系统首先对请求参数进行必要的校验，保证输入数据符合接口处理要求。对于部分统计类或查询频率较高的数据，业务逻辑层会优先判断缓存中是否存在有效结果；若缓存命中，则直接返回缓存数据，减少重复计算和数据库访问；若缓存中不存在有效数据，则继续执行相应的业务规则处理、数据统计计算和结果封装等操作。业务逻辑层在需要访问数据库时，会调用数据持久层提供的数据访问方法，由持久层完成具体 SQL 查询或更新操作。最终，业务逻辑层将处理结果封装为统一的响应对象，并返回给前端展示。

第四层为\textbf{数据层}。
数据持久层主要负责系统与数据库之间的数据交互。该层通过数据访问接口和映射文件对数据库操作进行封装，完成数据的查询、新增、修改和删除等操作。业务逻辑层不直接操作数据库，而是通过调用 MybatisPlus 这类 ORM 框架封装好的接口获取或更新数据，从而降低业务代码与数据库操作之间的耦合度。对于部分查询频率较高或计算开销较大的数据，系统会将处理结果写入 Redis 缓存，在后续请求中优先读取缓存数据。通过关系型数据库与 Redis 缓存的配合，数据层能够同时满足业务数据持久化和高频数据快速访问的需求。

\section{系统功能模块划分}
在上述分层架构的基础上，从业务维度对后端工程进行横向模块划分，将系统拆分为三个核心业务域：系统管理、公司运营管理和项目运营管理，以降低模块间的耦合度并提升代码的可维护性。从整体功能上看，项目管理模块主要围绕汽车电子软件过程管理展开，包括项目基础信息、缺陷、重大问题、风险、版本范围等功能；公司运营管理模块主要面向企业组织、员工、工时和KPI等运营数据，支持企业内部运营情况的统计分析；系统管理模块主要包括用户管理、角色管理、菜单管理、部门管理、权限管理和日志管理等功能，用于保障系统的正常运行。

其中，项目管理和公司运营管理承担主要业务功能，系统管理为业务模块提供用户、权限和菜单等基础支撑。本文根据毕业设计任务分工，重点对其中部分功能模块进行设计与实现，如图\ref{fig:function-module}所示。

\begin{enumerate}[label=(\arabic*)]
	\item \textbf{系统管理模块：}
	该模块对应后端 system 包，作为整个运营平台的底层基座，负责平台基础管理功能。其核心内容包括用户管理、角色管理、菜单管理、部门管理、日志管理、在线用户管理和权限控制。该模块为整个系统提供统一的认证授权基础，也是动态菜单和按钮权限控制的核心来源。这个模块是项目初始脚手架自带的，主要涉及八张数据库表。
	用户表 \verb|t_user| 存储系统登录账户信息，角色表 \verb|t_role| 存储角色定义，菜单表 \verb|t_menu| 存储前端动态菜单和按钮权限项，用户角色关联表 \verb|t_user_role| 和角色菜单关联表 \verb|t_role_menu| 用于构建 RBAC 权限模型，部门表 \verb|t_dept| 用于维护组织层级，日志表 \verb|t_log| 与 \verb|t_login_log| 用于记录用户操作和登录行为。
	
	\item \textbf{公司运营管理模块：}
	该模块对应后端 companyM 包，聚焦于企业人力资源的度量分析，主要负责员工、组织、工时、KPI 等企业基础管理和统计分析功能。其主要业务包括员工信息管理、组织结构查询、工时统计分析、KPI 指标统计。我负责该模块中“工时统计分析”下的 BU 工时分布功能。主要涉及四张数据库表：
	\verb|tb_emp_baseinfo| 存储员工基础信息，\verb|tb_org_tree| 存储组织树结构，\verb|tb_sync_wh| 存储从外部系统同步而来的工时记录，\verb|tb_sync_attend_hour| 存储考勤工时数据，用于计算加班工时。该模块既为项目管理提供人员和组织信息支撑，也为管理层提供多维度工时和绩效分析能力。
	
	\item \textbf{项目运营管理模块：}
	该模块对应后端 projectM 包，是系统的核心业务重镇，代码体量最大，主要围绕项目全生命周期管理展开，涵盖的子功能如图所示。我在该模块中负责的部分是项目基本信息维护、缺陷查询与统计以及重大问题管理。主要涉及以下几张数据库表：
	项目基本信息表 \verb|tb_project_baseinfo_new| 保存项目主档信息及里程碑进度，是多个业务子模块的基础数据源；\verb|tb_project_delivery_history| 用于记录项目近期交付信息的变更历史，支持交付节点的审计追溯。缺陷管理方面，\verb|tb_sync_bug|、\verb|tb_sync_jira|、\verb|tb_sync_bugclose| 等表用于从外部缺陷平台同步缺陷数据，实现多源缺陷的统一管理。为支持聚类维度的缺陷分析，\verb|tb_project_cluster| 将多个项目归入同一聚类，\verb|tb_project_cluster_user| 记录每个聚类对应的 SWPM（软件项目经理）负责人，\verb|tb_bug_cluster_daily_snapshot| 则存储每日聚类的缺陷快照数据，便于之后了解未解决缺陷数的变化趋势。此外，\verb|tb_project_serious_problem_new| 记录软件开发过程中的重大问题，用于重大风险跟踪与根因复盘。
	
\end{enumerate}

\section{本章小结}
本章主要对玄武数字化项目管理平台进行了总体规划与设计。首先从宏观角度阐述了系统的四层技术架构，包含前端展示层、安全拦截层、核心业务层与数据持久层，明确了前后端分离的通信机制及各层的核心技术栈选型。随后，从实际业务维度出发，将系统横向解耦为系统管理、公司运营管理和项目运营管理三大核心模块，并详细梳理了各模块的职责边界与所包含的具体功能。
