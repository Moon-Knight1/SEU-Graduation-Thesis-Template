第9页：技术亮点1 - 策略模式重构

内容要点：

  • 问题：缺陷查询接口用if-else分支处理三个数据源，违反开闭原则
  • 方案：定义BugPageQueryStrategy策略接口，三个实现类分别封装查询逻辑
  • 优势：消除条件分支，新增数据源只需添加策略类，符合开闭原则
  • 进阶：模板方法模式封装公共流程（分页参数处理、结果组装）

建议配图：策略模式类图（来自chapter5.tex）

第10页：技术亮点2 - 延迟关联优化

内容要点：

  • 问题：深分页查询LIMIT offset, N时，MySQL需扫描offset+N行再丢弃前offset行
  • 方案：先用覆盖索引查询当前页主键，再通过主键关联获取完整数据
  • 效果：优化前5K页平均35736ms → 优化后73.2ms，提升488倍

建议配图：深分页优化前后SQL对比图、性能对比表格

第11页：技术亮点3 - 索引优化

内容要点：

  • 问题：DATE_FORMAT函数导致work_date索引失效，全表扫描
  • 方案：将月份筛选改写为日期范围查询，避免在索引字段上使用函数
  • 效果：访问类型从ALL变为range，成功命中idx_wh_work_date索引

建议配图：SQL执行计划对比表

第12页：技术亮点4 - 防重复提交

内容要点：

  • 问题：用户连续点击提交按钮导致重复数据入库
  • 方案：自定义@RepeatSubmit注解 + Redis + 拦截器
  • 流程：拦截器判断注解 → 拼接Redis Key → 判断是否重复 → 放行或拒绝
  • 优势：注解式使用，代码复用，支持多模块

建议配图：防重复提交流程图（来自chapter5.tex）
